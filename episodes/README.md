# 台本の決まり（apsc-video）

台本（このフォルダの `*.json`）を書く・直す・監査するときの決まり。1005 のスキル `apsc-script` も同じ内容にそろえる。

## 1. 正しさが最優先
- 書いてよいのは、材料（IPA のシラバス・試験要綱・公表された過去問・解答例・採点講評）と、一般に確立した知識だけ。材料に無い数字・固有名・頻度（「よく出る」）を作らない。
- 断定しすぎない。シラバスの用語名をそのまま使う。

## 2. 冗長にしない（2026-10-08 本人）
> 「令和何年の応用情報技術者試験の IPA 公式の何ページに記されている指摘事項によると…」は本題と関係はあるけど冗長。伝えたい部分でないところは、齟齬が生じない範囲で削りたい。

- **出典は画面の隅（場面の `src`）と説明欄に任せる。** 台詞では年度・資料名・頁をくり返さない。問題を最初に紹介するときに1回だけ短く（「令和7年度秋期の午後問2」）。
- 採点講評は、意味を変えない短い言い方にする。
  - 「採点講評では、この設問は正答率が低かった、とあるわ」→「ここは、間違える人が多かったところよ」
  - 「…という誤答が散見された」→「〜と答えてしまう人もいたの」
  - 材料に無い意味は足さない（「難しい」「みんな間違える」などは言わない）。
- 1つの台詞で伝えることは1つ。前置き・言い直し・同じことの2回目は削る（まとめの章は除く）。
- 冗長かどうかの目安：その台詞を消しても、内容の正しさと分かりやすさが変わらないなら消す。

## 3. 形
- 字幕は1つ60字以内（`scripts/split_lines.py` で分ける）。英字の略語・問番号は `say` に読みを書く（SWOT→スウォット、問2→問い2）。
- 画面の型は `video/frame.html` のもの（title・list・levels・grid・forces・cards・qa・quiz）。
- 冗談は内容に関係するものを1章に1つまで。`joke: true`。ずんだもんの冗談の**すぐ次は、めたんの短い返し**（例「ふふ、それは重そうね。」`expr: "smile"`、中身の説明は入れない）。画面では返しに「…w」が付く（10/8 本人）。
- ショートの型（10/8 本人）：最初にずんだもんの勘違い（試験のひっかけ）→めたんが直す、「3秒で考えてみて」、似ている用語の対決は使う。コメント欄へ誘う台詞・終わりを最初につなげる形は使わない。
- 午前の過去問の1問ショートで問題文が長い（だいたい50字を超える）ときは、最初にめたんが「〜を選ぶ問題よ」と1文で要約する（答えは言わない。10/9 本人「ショートで長文を読む人はいない」）。
- 例え話の会社・お店は架空と断る。

## 4. 監査
- 10/9 から：1回目の監査と直しは 1005（指示書 Opus-13、書いたときとは別のセッション）。そのあと、書いた AI とは別の AI（Codex、GPT）が最後の確認をする。`scripts/produce.py` が「監査 → 直し → 再監査」を最大3回くり返し、「可」になった台本だけを投稿の棚（`queue/`）に入れる。
- 監査の観点：誤り・材料との食い違い・言い過ぎ・出典・読み・冗談・**冗長**。
